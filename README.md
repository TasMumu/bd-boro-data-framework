# bd-boro-data-framework

An open, tested data engineering framework for integrating official crop
statistics with satellite and climate data, applied to district-level Boro
rice in Bangladesh: all 64 districts, harvest years 2011–2025.

The pipeline (Python + DuckDB) extracts the district Boro rice tables from
the Bangladesh Bureau of Statistics (BBS) Yearbooks of Agricultural
Statistics, 2012–2025 editions. It checks every value against unit
identities, the printed national totals and a second edition, and aligns it
by harvest year with MODIS NDVI, ERA5-Land climate, and JRC and Sentinel-1
flood fractions. Only values printed in the yearbooks are used; nothing is
interpolated or imputed.

## Contents

| Folder | Contents |
|---|---|
| `v2/` | code, tests, notebooks, outputs and manuscript sources; start with [`v2/README.md`](v2/README.md) |
| `v2/data/` | the Bronze, Silver and Gold layers, including the Earth Engine extracts and the Gold panel `v2/data/gold/bangladesh_agri_v2.duckdb` |
| `v2/notebooks/` | `01_Data_Engineering_Pipeline.ipynb` builds the dataset step by step with its documentation; `02_Evaluation_and_Outputs.ipynb` documents the evaluation and outputs |
| `data/bronze/` | where the downloaded BBS yearbooks and GADM boundaries go; they are not redistributed (see [`data/bronze/README.md`](data/bronze/README.md)) |

## Quick start

All commands are run from the repository root, after placing the downloads
in `data/bronze/`.

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r v2/requirements-lock.txt   # Windows
# .venv/bin/python -m pip install -r v2/requirements-lock.txt     # Linux/macOS
.venv/Scripts/python v2/run_all.py
```

Setup, the failure tests and the fresh-setup test are described in
[`v2/README.md`](v2/README.md).

## Manuscript

The repository accompanies the manuscript "An open, tested data engineering
framework for integrating official crop statistics with satellite and
climate data: district-level Boro rice in Bangladesh" by Tasnim Ahmad Mumu
and Rezaul Karim. The manuscript is generated by the pipeline from
`v2/paper_ems/parts`, so every number, table and figure in it comes from the
outputs in this repository.
