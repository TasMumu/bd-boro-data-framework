# Fresh-setup reproducibility test

Run with `python v2/tests/run_fresh_setup_test.py`. Results of the run
reported in the manuscript: `fresh_setup_summary.json` (date 2026-10-30) and
`fresh_setup_comparison_A.csv`, `fresh_setup_comparison_B.csv`.

Machine: Windows 11, 16 logical CPUs, 16 GB RAM, Python 3.13.7, pandoc 3.7.0.2.

## Purpose

To check that someone following `v2/README.md` from a clean state can rebuild
every output and get the same results, and to list what they need from
outside the repository.

## Procedure

1. A new folder is set up with only what a clone of the repository plus the
   documented downloads contain:
   * from the repository: `v2/src`, `v2/tests`, `run_all.py`, both
     requirements files, the README, the dashboard script, the manuscript
     sources (`paper_ems/parts`, `highlights.md`, `references.json`), the
     results of the previous fresh-setup test and of notebook 01
     (`docs/*.json`, `docs/*.csv`), which the manuscript quotes, the 53
     cached Earth Engine extracts with `extraction_times.json` and
     `extraction_dates.json`, and the two files kept in the repository rather
     than generated (the dashboard screenshot, Figure 5, and the record of the
     one-off Sentinel-1 single-band check);
   * the external inputs the README asks users to download: the 14 BBS
     yearbook PDFs (2012–2025 editions) and the GADM v4.1 level 0 and level 2
     shapefiles (copied from this checkout).

   No generated file is present: no BBS CSVs, manifest, Silver or Gold
   tables, crosswalk, data dictionary, tables, figures, validation report,
   failure-test results or manuscript.
2. For each of two requirements files a new virtual environment is created
   and the file installed:
   * **A, `requirements.txt`** (direct dependencies pinned). The installer
     chose versions different from the lock file for 64 of the 103 packages,
     including shapely 2.2.0 (lock: 2.1.2) and pyproj 3.8.0 (lock: 3.7.2).
   * **B, `requirements-lock.txt`** (all 103 packages pinned). All versions
     matched the lock file.

   `pip check` reported no broken requirements in either environment.
3. In each environment, in a fresh copy: `python v2/run_all.py`, then
   `python v2/tests/run_failure_tests.py`, then the manuscript build
   (`s06_manuscript.py paper_ems`), as in the README.
4. Every generated file is compared with the outputs of this checkout by
   `tests/compare_outputs.py` under these rules:

   | Class | Rule |
   |---|---|
   | identical | SHA-256 of the two files equal |
   | same content | the format stores write times or folder paths: DuckDB, every table equal value by value; Word, every document part equal, ignoring the write times stored in the zip container; logs, equal after removing the folder path |
   | run time only | the only differences are measured run times (the timing record, and the run-time table and sentence of the manuscript in its Markdown and Word versions) |
   | kept in repository | not generated by the pipeline; checked for presence |
   | DIFFERENT | anything else, or a missing file: the test fails |

   The classes are mutually exclusive: every file falls in exactly one.

| Baseline run | PASS (whole chain from the parsed rows; BBS table and Gold panel identical) | same |
| Gold panel SHA-256 | equal to the reference (5cbaeb1edaef…) | equal |
| Files compared | 57 | 57 |
| identical | 42 | 42 |
| same content | 10 | 10 |
| run time only | 3 | 3 |
| kept in repository | 2 | 2 |

The 42 identical files include all extracted BBS tables and checks, the
manifest, all Silver Parquet files, the crosswalk and data dictionary, the
validation report, every analysis table, `results.json` and every generated
figure. The 10 same-content files are the Gold DuckDB database (all 8 tables
equal value for value), seven failure-test logs (only the folder path in the
tracebacks differs) and two Word files (the reference template and the
highlights; only the zip container's write times differ). The 3 run-time-only
files are the timing record and the manuscript in its Markdown and Word
versions (only the run-time table and the sentence quoting the total run
time differ). Of the 57 files, 55 are generated outputs and 2 are kept in the
repository.

Earth Engine was not contacted: all 53 cached extracts passed the
completeness test, so no account or authentication was needed.

## Problems found and fixed through this test

1. **Manifest dates.** The manifest recorded each file's modification time,
   which changes whenever files are copied or cloned, so a fresh setup could
   not reproduce the manifest. Extraction dates are now written by `s02` to
   `gee/extraction_dates.json` when an extract is computed and copied into the
   manifest; PDFs and GADM files are identified by SHA-256.
2. **District areas.** With the newer shapely and pyproj of environment A,
   `area_km2` differed in the 15th significant digit (at most 4 × 10⁻¹² km²).
   Areas are now rounded to 0.001 km². No analysis result changed.
3. **Indirect dependencies.** `requirements.txt` pins only direct
   dependencies; `requirements-lock.txt` now pins all 103 packages. Both
   reproduce the results.
4. **Manuscript build in a clean copy.** Inside `run_all.py` the manuscript is
   built before the failure tests have run; the build failed when no
   failure-test results existed. It now marks the manuscript as a draft
   instead, and the manuscript is rebuilt after the tests.
5. **camelot clean-up message.** On Windows, camelot sometimes cannot delete
   its temporary page files when the PDF step exits and prints
   `Exception ignored in atexit callback ... PermissionError`, after all
   outputs are written. It changes nothing; the README notes it.

## Not covered by this test

* The test ran on the same computer as the original run, in a separate folder
  and new environments; Linux and macOS were not tested.
* The BBS PDFs and GADM files were copies of the files used, so their
  checksums match by construction; downloading them again from the
  publishers was not tested.
* Re-extracting all Earth Engine data from scratch was not repeated. Two
  extracts of harvest year 2016 were recomputed: Sentinel-1 through the
  single-band path, and NDVI in notebook 01; both equal the cached extracts
  within 10⁻¹⁶ (`docs/notebook_rebuild_summary.json` for NDVI).
